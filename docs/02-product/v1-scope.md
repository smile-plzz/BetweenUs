# V1 Scope

## V1 questions

**Will two people form the habit of intentionally preserving “we should” ideas in a shared space because they trust those ideas will become useful later?**

And:

**Will lightweight shared interactions—especially Question Cards—give the couple a reason to inhabit the space together rather than treating it only as a bookmark database?**

The broad product has five pillars: Shared Memory, Presence & Expression, Intimacy & Desire, Shared Decisions & Discovery, and Shared Living. V1 does not fully build all five, but it should test more than storage alone.

## V1 behavioral loops

### Loop A — Capture
1. Partner A encounters something relevant to the couple.
2. They share it to BetweenUs in seconds.
3. Partner B sees/reacts.
4. Later the item resurfaces at a useful moment.
5. The couple acts on it.
6. It becomes shared history.

### Loop B — Expression
1. A partner places a Question Card or lightweight expression into the shared room.
2. The other partner notices it without entering a chat thread.
3. They answer, pass, choose Not now, or leave it unanswered.
4. Submitted responses become shared context.
5. The interaction can influence future prompts, decisions or understanding without becoming a score.

## Must have

### 1. Pairing
Two adult accounts enter one shared space through an explicit invite and understand that intentionally submitted content is shared.

### 2. Quick capture
- paste URL;
- share-sheet target where technically feasible;
- quick manual text item;
- optional one-line context;
- save succeeds even when enrichment fails.

### 3. Shared collection
- objects visible to both;
- source + contributor;
- automatic/basic categories;
- search/filter;
- recent/saved views.

### 4. Independent reactions
Both users can signal interest with extremely low friction. Disagreement remains visible and valid.

### 5. Shared Question Cards — prototype core
- either partner can create/send a question into the room;
- a small curated set of suggested prompts;
- answer / pass / not-now / unanswered states;
- submitted answers visible to both;
- no conventional chat thread;
- no unanswered-count guilt or response pressure;
- support at least ordinary/playful prompts and a carefully scoped adult intimacy category.

This tests whether BetweenUs can become a shared emotional space rather than only a storage utility.

### 6. Decision entry points
At minimum:
- Watch something;
- Eat / go somewhere;
- Do something.

Return only a few saved candidates.

### 7. Explain resurfacing
Explain why an item fits: partner saved it, both liked it, still untried, fits a constraint, etc.

### 8. Completion
Mark ordinary items watched/tried/visited/done and collect lightweight reactions.

### 9. Simple return experience
A calm set of meaningful traces since the last visit, not an unread inbox.

## Intimacy in V1

Intimacy & Desire is a **core product pillar**, but V1 should test the interaction model rather than attempt a comprehensive sexual feature suite.

V1 can include:
- an intimacy Question Card category for consenting adult pairs;
- user-written intimate questions;
- transparent submitted answers;
- Pass / Not now;
- discreet notification copy;
- storage/security treatment appropriate for sensitive text.

V1 does not need:
- a giant kink taxonomy;
- sexual compatibility percentages;
- automated sexual-performance history;
- aggressive AI-generated escalation;
- explicit-media hosting before its security/platform implications are designed.

This distinction keeps intimacy foundational without letting one domain consume the entire validation build.

## Should have if inexpensive
- Open Graph metadata;
- duplicate URL detection;
- basic price/distance fields;
- rough budget constraint;
- PWA/mobile-first behavior;
- export of couple-space data;
- simple “leave for you” trace;
- a small set of affectionate/playful gestures.

## Explicitly not V1
- full chat;
- live location;
- bank integration;
- expense accounting;
- large external recommendation engine;
- rich calendar integration;
- comprehensive household management;
- complex autonomous AI agent;
- relationship analytics;
- compatibility scoring;
- gamified streaks;
- comprehensive explicit-content/media system;
- 3D room/avatar world;
- Wayfare migration.

These exclusions protect the experiment, not the long-term vision.

## UX performance hypotheses
- common share-to-save flow ≤ 5 seconds after choosing BetweenUs;
- no mandatory categorization during capture;
- reaction one tap;
- Question Card participation understandable in seconds;
- Pass/Not now no harder than Answer;
- decision setup preferably ≤ 3 inputs;
- default recommendation set 3 candidates.

## Exit criteria
Proceed toward broader development if a 30-day pilot shows:
- both members contribute;
- capture continues after novelty week;
- saved items resurface and lead to action;
- users return at decision moments without prompting;
- users voluntarily send/respond to Question Cards;
- Question Cards feel meaningfully different from messaging;
- at least some couples use the shared space for candid/affectionate/intimate expression without feeling pressured;
- qualitative shared ownership: “our app”, “save it there”, or equivalent.

If only utility features retain, investigate whether the digital-home thesis is too broad. If expression retains but capture does not, reconsider the wedge. If intimate prompts create pressure or confusion, redesign participation and consent signaling before expansion.
