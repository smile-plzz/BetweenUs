# Feature Map

This map separates the **long-term product surface** from **validation scope**. Inclusion here does not mean a feature should be built now.

## A. Foundation

### Pairing & identity
- exactly two members per couple space;
- invite/accept pairing;
- equal membership;
- profile identity/avatar;
- relationship-space settings;
- unpairing/data-handling policy (must be designed before production).

### Shared object system
- links;
- text/notes;
- images/screenshots;
- generic saved objects;
- source attribution;
- automatic categorization;
- search/filter;
- archive/history.

## B. Capture & Memory — **V1 core**

- share-sheet capture;
- paste URL;
- manual quick-add;
- preserve source;
- automatic title/preview/type extraction;
- optional tiny annotation (“why I saved this”);
- partner attribution;
- reactions/ratings;
- completed/experienced state;
- resurfacing;
- semantic retrieval later.

### Candidate categories

Categories should be views over shared objects, not separate databases wherever possible:

- Watch — movies, shows, videos;
- Listen — songs, albums, podcasts;
- Eat — restaurants, dishes, recipes;
- Go — places, dates, activities;
- Do — games, experiences, events;
- Read — books/articles;
- Want — products, clothing, jewelry, gift signals;
- Travel — destinations/trips (Wayfare-adjacent);
- Intimacy — explicitly shared romantic/sexual ideas or content;
- Other — everything not worth forcing into taxonomy.

## C. Decision Support — **V1-lite / V1.1**

### Intent prompts
- What should we watch?
- What should we eat?
- What should we do?
- Where should we go?

### Constraints
- time available;
- rough budget;
- distance/travel time;
- mood/energy;
- at home / go out;
- content category.

### Output
- 3–5 candidates;
- reason each candidate fits;
- source: saved by partner / saved by self / mutually liked / discovered;
- quick mutual vote;
- “pick for us” only after sufficient trust/data.

## D. Discovery — **Post-validation**

- small contextual recommendation sets;
- nearby activities/events;
- recipes;
- books/media;
- places;
- games;
- explicit “why this” explanation;
- dismiss/not interested feedback;
- no default infinite feed.

## E. Presence & Expression — **Vision / selective prototype**

The objective is co-presence, not messaging.

- online/in-room presence where mutually enabled;
- tap/poke;
- kiss/affection gesture;
- playful customized gestures;
- “leave something for you”;
- song/photo/note as an object in the room;
- subtle room changes/traces;
- synchronous lightweight reactions;
- activity presence only with explicit expectations.

Avoid building a parallel chat thread.

## F. Return / “While you were away”

- partner left something;
- a few newly captured ideas;
- old item newly relevant;
- shared goal approaching;
- upcoming moment;
- no unread-count guilt;
- no streak-loss mechanics.

## G. Shared Living — **Later**

### Lists
- groceries;
- shared shopping;
- errands;
- lightweight household lists.

### Plans
- date ideas;
- upcoming activities;
- shared reminders;
- calendar context/integration.

### Goals
- trip goal;
- purchase goal;
- experience goal;
- progress without contribution competition.

## H. Money as Decision Support — **Later**

- rough date budget;
- activity affordability;
- shared purpose funds;
- trip-fund target/progress;
- recommendation filtering by desired spend.

Explicitly avoid by default:

- debt ledger;
- “who paid more” score;
- partner spending alerts;
- judgmental budget policing.

## I. Places & Travel — **Wayfare relationship**

- saved places;
- distance/travel time;
- rough price;
- date suitability;
- trip possibilities;
- contextual “where can we go?” decisions;
- future handoff/integration with Wayfare.

## J. Intimacy — **Later, safety-sensitive**

- explicitly shared fantasies/ideas;
- consensual intimate gestures;
- sensitive media;
- private-to-couple presentation;
- discreet notifications;
- consent/preferences controls;
- no sexual-performance scoring or pressure mechanics.

## K. Memory after doing

- watched/visited/tried/did state;
- separate partner ratings;
- shared photo/memory attachment;
- date/time;
- “would do again”;
- future recommendations informed by actual outcomes.

## L. Intelligence layer

Cross-cutting rather than a destination tab:

- classification;
- metadata extraction;
- duplicate detection;
- preference learning;
- mutual-fit ranking;
- contextual resurfacing;
- recommendation explanations;
- time/budget/location reasoning;
- semantic search;
- eventual proactive nudges with strict notification restraint.
